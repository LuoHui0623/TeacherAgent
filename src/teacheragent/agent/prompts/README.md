# 提示词结构规范

本目录是提示词资产的唯一位置。每份提示词描述一个角色或一项任务，结构固定，便于比对、审查与修改。

## 文件结构

```md
# <主题>

## 角色

## 目标和要求

## 约束

## 输出契约

### 契约要求说明

### 结构化输出

## 输入            （有注入内容时必需；固定放最后）
```

标题不是固定模板：按提示词实际需要增删小节，例如需要示例时增加 `## 示例`。顺序保持「你是谁 → 要什么 → 不能做什么 → 交什么 → 收到什么」。

## 各节职责

| 小节 | 写什么 | 不写什么 |
|---|---|---|
| `# 主题` | 一句话定位，与文件名语义一致 | — |
| `## 角色` | 你是谁、产出什么、不负责什么 | 字段定义与输出规则 |
| `## 目标和要求` | 本次任务要达成的结果，以及决定结果的原则 | 字段定义 |
| `## 约束` | 边界与禁止事项：下游职责、不可改动项、审批关系 | 输出字段与 JSON |
| `## 输出契约` → `契约要求说明` | 契约的语义要求：字段含义、引用规则、禁止输出的字段、返回前自检 | JSON 样例；系统分配的身份字段 |
| `## 输出契约` → `结构化输出` | 可直接解析的输出样例 | 解释性文字 |
| `## 输入` | 注入字段清单，以及承载它们的 `${{ 名称 }}` 占位符 | 具体值；等待填充的空标签 |

## 一条事实一个位置

- 字段定义只写在 `契约要求说明`；`目标和要求` 引用它，不复制字段清单。
- 注入字段清单只写在 `## 输入`；其它小节引用它，不重列。
- 模型只输出它该产出的字段。**系统分配的身份字段**（大纲 / 节点 / 运行标识等）不写进契约，由调用方在入库时补齐；模型需要引用其它对象时，用业务名称（如章节标题）引用，由调用方解析成标识。
- 同一要求不在一份提示词里出现两次。出现两次，说明有一处该删。
- 「不负责什么」写在 `角色` 与 `约束`，不在每个小节重复。
- 输出禁止项（例如不输出某个字段）写在 `契约要求说明`，不散落到 `约束`。
- 与模型的往返约定（是否包代码块、是否只输出 JSON）写在 `契约要求说明` 的第一条。

## 模板与注入

本目录下的文件是 **提示词模板**：加载时解析出正文里的 `${{ 名称 }}`，渲染时按绑定表替换，发往 provider 的那一条消息就是渲染结果。

一份文件是不是模板，**只看有没有 `${{ 名称 }}`**；没有任何占位符的是纯静态提示词，整份就是一条消息。

```python
from teacheragent.infrastructure.llm.prompts import load_prompt, render_prompt

messages = render_prompt(
    load_prompt("agent/prompts/outline-architect.md"),
    {"brief": {...}, "learnerProfile": {...}},
)
```

绑定表的键就是模板里的变量名；两者必须对得上。模板声明的每个变量都是必需变量，缺一即报 `PromptRenderError`，发生在发往 provider 之前。

| 规则 | 说明 |
|---|---|
| 写法 | `${{ 名称 }}`，名称限 `[A-Za-z_][A-Za-z0-9_]*`，允许空格。 |
| 变量清单 | `Prompt.variables` 按首次出现顺序列出名称（去重），即该模板的必需变量；不重复出现的名称只算一个。 |
| 注入值 | 字符串原样写入；其它值按带缩进的 JSON 写入（`ensure_ascii=False`）。 |
| 缺失 | 模板声明了名称但绑定表没有该项时，渲染报错，不静默留空也不留占位符。 |
| 嵌套 | 替换是一次性的：注入值里出现的 `${{ 名称 }}` 不会被再次展开。 |
| 切分 | 静态前缀 = 第一个声明变量的段落之前的正文；注入载荷 = 从那个段落起直到文末。段落之间以空行分隔。 |
| 位置 | 声明变量的段落通常在模板最后（写在 `## 输入` 里），它之前的角色、规则与契约是跨调用不变的静态前缀。 |
| 声明 | 模板用 `## 输入` 列出字段与形状；注入值不在模板里写死。 |

### 渲染成几条消息

由模板结构决定，调用方不用选：

- 没有 `${{ 名称 }}`：整份模板渲染成一条消息（默认 `system`）。
- 有 `${{ 名称 }}`：静态前缀渲染成一条消息（默认 `system`），注入载荷渲染成另一条（默认 `user`）。每次调用变化的输入因此独立成一条消息，静态规则保持稳定前缀。

角色可以改（`render_prompt(..., role=..., payload_role=...)`），但「分几条」不由参数决定。

模板以声明变量的段落开头时没有静态前缀可用，加载期报 `PromptFormatError`。把声明变量的那段往文末放，它之前的规则才会进 system 消息。

不要把片段插进规则中间：声明变量的段落之后的内容会跟着载荷进 user 消息，不再属于静态前缀。

## 写作要求

- 用陈述句直接说规则，不使用比喻。
- 编号只用于有顺序要求的清单；无顺序的列举用 `-`。
- 术语与 `src/teacheragent/docs/` 的领域用词一致（画像、大纲、章节、美化）。
- 中文字段说明与英文字段名并存；字段名使用仓库既有命名，不另造同义词。
- 一处规则只写一次；需要强调时改写措辞，不重复整句。

## 资产与加载

- 加载入口：`load_prompt("agent/prompts/<名称>.md")`，它读资产并把这一版正文冻结进 `prompt_snapshots`；只读场景（读接口）用 `read_prompt`，它不写快照。
- 每份资产声明自己的变量清单（`Prompt.variables`），调用方按同名键提供绑定表；节点执行时资产身份经 `WorkflowCallOrigin` 写进 `llm_runs` 的 `prompt_ref` / `prompt_content_hash`，渲染结果写进 `prompt_sources_json`。
- 本 README 不参与加载，但它的路径形状满足加载器的校验；除提示词资产与本文件外，不要把其他文件放进本目录。
- 提示词正文变更随代码提交，由 Git 记录版本；内容哈希在加载时计算。

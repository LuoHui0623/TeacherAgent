## 结构化并发与任务生命周期

自由漂浮的后台 Task 很容易在请求结束后继续运行，造成资源泄漏、异常丢失和状态竞争。结构化并发要求子任务属于一个明确的作用域，并在作用域结束前完成或取消。

### TaskGroup 的失败传播

Python 3.11 的 `asyncio.TaskGroup` 会等待组内任务结束；当一个任务失败时，其他任务会收到取消信号，异常最后以异常组的形式向上传播。

```python caption="把一组并发请求绑定在同一个作用域"
import asyncio

async def load_item(item_id: int) -> str:
    await asyncio.sleep(0.05)
    if item_id == 3:
        raise ValueError("item 3 is unavailable")
    return f"item:{item_id}"

async def load_all() -> list[str]:
    results: list[str] = []
    async with asyncio.TaskGroup() as group:
        tasks = [group.create_task(load_item(item_id)) for item_id in range(1, 5)]
    results.extend(task.result() for task in tasks)
    return results
```

### 取消是协议，不是普通异常

收到取消时应尽快释放连接、锁和临时文件。清理逻辑可以放在 `finally` 中，但不要无意中吞掉 `asyncio.CancelledError`，否则上层无法判断任务是否真的停止。

:::warning{title="避免无主任务"}
只有在明确设计了生命周期、异常处理和关闭策略时，才把 Task 放入长期运行的后台集合。
:::
